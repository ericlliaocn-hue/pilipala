## 背景与现有流程

`web/src/components/canvas/canvas-node-angle-dialog.tsx` 提供水平角、俯仰角、镜头距离和镜头类型设置；`project.tsx` 的 `generateAngleNode` 固定 `count: "1"`，用当前图片走 `requestEdit`，单次成功后在右侧创建一个普通图片节点并连回源节点。工具栏中的「多角度」目前是可配置的隐藏工具，不是角色卡或三视图工作流。现有节点请求有 AbortController、loading/error 状态和素材上传流程，应复用这些机制；不另建任务或供应商通道。

## 业务目标

从角色参考卡的图片发起三视图生成，继续使用当前图片模型与图生图请求，把结果放到画布并可通过既有组、连接和显式 `@` 引用作为后续角色参考。生成结果只提高复用便利性，不承诺供应商能保证角色像素级一致。

## 已确认的输出与计费合同

用户选择：**生成一张包含正面、侧面、背面视图的排版图；恰好一次图生图请求，按现有一次生图行为计费；只创建一个普通图片节点。** 不发三次请求、不自动拆成多个图片节点。用户之后可以通过现有手动切图工具自行拆分，或直接引用整张排版图。

## 已有链路与约束

- 图片工具栏：`canvas-image-toolbar-tools.tsx` 的 angle 工具定义，当前 `defaultVisible: false`；`canvas-node-hover-toolbar.tsx` 把所选工具回调交给 `project.tsx`。
- 页面：`project.tsx` → `CanvasNodeAngleDialog` → `generateAngleNode`。
- 生成：`buildGenerationConfig(effectiveConfig, node, "image")` → `requestEdit(config, prompt, [source image], {signal})` → `uploadImage` → 更新普通图片节点。
- 提示词：`buildAnglePrompt` / `buildAngleLabel` 位于 `canvas-generation-helpers.ts`，角度参数类型与 UI 位于 `canvas-node-angle-dialog.tsx`。
- 角色卡连接：复用 1.4a 角色卡上的图片、既有组/连线与 Config `@[node:…]`；不新增隐式注入。
- 安全和费用：不绕过现有 AI 配置校验、参考图解析、请求取消、托管模式和计费行为；不发真实生成/计费调用用于代码验收。

## 行为合同与验收

1. 在现有「多角度」交互内提供三视图模式，不新增平行图片生成入口，不改变单视角已有参数和结果。
2. 三视图模式以源图片作为唯一参考，使用当前图片模型和画布既有图生图调用；每次确认严格调用一次 `requestEdit`，配置 `count: "1"`，一次成功只上传一次结果并追加一个普通图片节点。
3. 提示词明确要求同一角色的正面、侧面、背面视图放在一张干净的三视图排版图中，保持外观、发型、服装、配色和风格一致；不要额外生成标题/说明文字。输出质量仍由模型决定，不承诺绝对一致。
4. 成功结果放在源图片右侧并连回源图片，沿用既有尺寸、素材存储、loading/success/error、请求取消与计费路径。若源图片属于 1.4a 角色卡组，新结果保持为普通独立节点，不自动写入原角色组；用户可自行打组或直接通过 Config `@` 引用新节点。原图与原组成员不被改写。
5. 空图或 AI 配置未就绪时，不发请求、不追加半成品；请求失败沿用现有错误显示与重试行为；取消或删除期间不得把已取消请求的迟到结果写回，也不得将结果节点永久留在 loading。刷新中断沿用既有 `resetInterruptedGeneration` 恢复行为。
6. 单视角模式回归：原参数、提示词、单次图生图和单图片节点结果不变。
7. 使用生产回调或等效入口测试验证确切服务调用次数为 1、count 为 1、成功后新增节点数为 1；测试源图不变、请求失败、取消、删除源节点、连续生成竞争/状态收尾以及单视角回归。测试生成服务使用受控 stub，不发真实请求或扣费。
8. 角色卡组/图片可以照既有方式通过连接或显式 `@` 作为后续参考；本切片不改 generation context 注入算法。确认新图片可被现有引用函数读取。
9. 外置 Chrome 可见窗口验证模式切换、预览说明、按钮启停、生成后节点布局和失败/取消显示；按每轮实际浏览器可用情况记录，不以组件测试替代页面验证。

允许修改现有角度弹窗、页面 `generateAngleNode` 与必要的本地化、测试、CHANGELOG、pending-test 和工程状态文档。若需要改写通用引用、存储、计费、认证、模型 API、任务状态、重试次数、超时或并发上限，先停下并报告证据，不扩范围。既有取消/删除入口的错误只在维持上述合同所必需的范围内修正并覆盖测试。
