## 执行流程

角色：编排模型按用户当前指定执行；当前 GPT-6 Astra（Codex，reasoningEffort ultra）先完成 1.3 的修复与完整验收，再按 [编排试验](./orchestration-trial.md) 比较 GPT-6.1 Terra；只读合同评分不作为切换条件。实现 DeepSeek V4.1 Flash（OpenCode `tokenbridge/deepseek-v4-1-flash-261017`，variant high）；验收 Grok 4.7（Cursor `grok-4.7`，只读审查）。模型或渠道不可用时如实报告，不擅自换角色。推理档位不代替验收。

1. **接手与规划**：编排者核对仓库、分支、实际提交、工作区与遗留 worktree；区分已实现、已验证、未验证和阻塞。对照愿景、里程碑、现有同类实现和真实调用链，写出业务结果、范围、隔离维度、依赖与授权。接手前的报告只能作为线索，不能直接当作代码事实。
2. **明确合同**：新功能按 brief 模板写出成功、失败、重试、取消、刷新、并发、删除、既有功能交互及用户数据处理等适用场景；每项写可观察结果和验证方式。不适用项说明原因。设计涉及共享行为、配置、安全链路、数据库或覆盖用户数据时，按项目规则先说明并取得明确确认；未知事项标为待决，不让实现者猜。
3. **实现与自检**：DeepSeek 在隔离 worktree 对照 brief 实现，保留既有改动，不扩范围。交付记录包含基线和最终提交或未提交 diff、实际改动文件、逐项验证结果、未测项及风险；普通功能无需为每个实现细节编写测试，关键用户路径和失败路径要有可验证证据。
4. **独立验收**：Grok 对照完整 brief、最终 diff 和成熟同类实现审查，区分阻塞问题与风险，列出可复现证据。返工后的复验既检查修复，也检查受影响的完整流程；不得把局部复验通过说成全功能通过。编排者独立复核代码、关键路径和适用验证，不只转述 Grok 结论。
5. **状态与推进**：每个验收项标记通过、失败或未验证并记录证据；未验证不是通过。实现中、待验收、验收不通过、已验收和已合并分别记录；代码、文档与提交 SHA 必须对应。对照 VISION、MILESTONES、用户约束及下一步依赖做纠偏；合并和推送按用户授权及项目规则执行，然后进入下一步。

交接记录至少包括：业务目标与下一步、仓库/worktree/分支/基线及目标提交、未提交文件、已验证与未验证项、审查发现和阻塞、运行中的委派任务、合并推送部署权限。恢复前读取实际状态，旧任务完成或取消后再派新任务；不得声称未运行的任务正在执行。状态记录不包含密钥。

### 交付关卡

- 派工前：编排者给执行者目标、基线、允许修改范围、现有流程、逐项验收和禁止事项；未确定的产品行为标为待决。没有完成这些信息，不能进入实现。
- 执行后：执行者提供实际 diff/提交、改动文件、逐项验证证据和未验证项；失败或缺失的检查不写成通过。编排者核对变更范围和基线。
- 验收后：审查者标明审查的完整范围及逐项结论；编排者亲自核对关键代码、证据、失败路径和共享行为。只复验补丁不等于整项验收通过；阻塞问题未关闭或要求的验证未完成时，不得标记已验收或合并。
- 交接或等待时：记录可定位的任务状态和下一步；只在取得实际结果后报告完成，不把等待、超时或历史结论描述成当前通过。可独立推进的事项继续推进。
- 检查强度匹配风险：低风险小改动可以合并简化交付记录；共享状态、用户数据、安全或计费链路保留完整场景和独立验收。清单与 CI 不能替代真实行为验证。

遇到以下情况必须停下来问人：超时 / 重试 / 大小上限等边界值、定价与积分、需要开通的 Key 或账号、资质备案、生产部署。

## 已知遗留

- `Dockerfile` 用 `oven/bun:1.3.13` 且不带 `--frozen-lockfile`：bun 1.3 读不了 `web/bun.lock`（v2），会忽略锁文件重新解析依赖（本地实测解析出 antd 6.6.7 而非锁定的 6.4.2）。改发布流程时一并升级到 bun 1.4.x 并加 `--frozen-lockfile`。
- `web/bun.lock` 只含 darwin-arm64 的原生可选依赖（缺 rollup / esbuild / tailwind oxide 的 linux、win32 条目；`admin/bun.lock` 是全平台的），Linux 上 frozen 安装后 `vite build` 找不到 `@rollup/rollup-linux-x64-gnu`。CI 的 web job 暂时跑在 `macos-latest`；需要用全平台方式重新生成 `web/bun.lock`（会变更依赖锁，需单独一步验收），之后 web job 和 Docker 构建都能在 Linux 上用 frozen 安装。
- worker 仍保留 Anytoken 直连视频轮询路径（`AnytokenGatewayAdapter`，2s × 90 次上限）；已上架 Seedance 产品走 NewAPI，不经过该路径。后续确认无用后清理。
- 公开文档 `docs/content/docs/overview/features.mdx` 仍按上游「浏览器直连」口径描述，需在合适步骤按托管产品改写。
